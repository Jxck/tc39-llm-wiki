## Normative: In PluralRules, set compactDisplay only if notation is "compact"

- slide: [link](https://docs.google.com/presentation/d/1qKRDsbRbEw9zKfmCAwqTXdDbTAdyc4IArr2C0-v4vIc)
- [FYT](../../people/FYT.md) presented ecma402 PR [#1032](https://github.com/tc39/ecma402/pull/1032). `Intl.NumberFormat` reads `compactDisplay` unconditionally but stores it only when `notation` is `"compact"`, while `Intl.PluralRules` stored it unconditionally. So its resolved options could never report `undefined`, which was inconsistent and cost V8 extra memory.
- The PR makes PluralRules store it only for compact notation, like NumberFormat. [DLM](../../people/DLM.md) supported it. [SFC](../../people/SFC.md) said TG2 had already approved it in November.
- Conclusion: consensus on the PR.

## Normative: make re-exporting a namespace object in 2 steps behave like 1 step

- slide: [link](https://docs.google.com/presentation/d/1Ozx51idOUlBzJz8nPgvB8U5HypIN7o0w7mfEaL0xBSs/edit?usp=drivesdk)
- [NRO](../../people/NRO.md) presented ecma262 PR [#3715](https://github.com/tc39/ecma262/pull/3715) (written by [KG](../../people/KG.md)). When the same name reaches a module through two `export * from` paths, it is an ambiguous-binding error unless both resolve to the same binding. `export * as ns from "dep"` already passes that check, but `import * as ns from "dep"; export { ns }` creates a new local binding and errors.
- The PR treats the two-step form like the one-step form, which removes some ambiguous-binding errors. Engines are inconsistent today: SpiderMonkey and JSC match the spec, V8 and XS do not.
- [MAH](../../people/MAH.md) asked for test coverage of aliasing cases. [MAH](../../people/MAH.md), [GCL](../../people/GCL.md), and [DLM](../../people/DLM.md) supported it.
- Conclusion: the normative PR has consensus.

## `Error.captureStackTrace` for Stage 2

- wiki: [Error.captureStackTrace](../../proposals/error-capture-stack-trace.md)
- proposal: [proposal-error-capturestacktrace](https://github.com/tc39/proposal-error-capturestacktrace)
- slide: [link](https://docs.google.com/presentation/d/1c3vpsgkUSD2qWCl_6RICnykWLYm2Tc7Dk_uusBKNvc8)
- [DLM](../../people/DLM.md) presented spec text with an implementation-defined choice: install a data property, or install accessors. In the accessor version, a dynamically added internal slot holds the stack, the getter returns it, and the setter replaces the accessor with a data property.
- [JHD](../../people/JHD.md) objected to leaving the choice open. The committee agreed to mark the accessor approach as legacy, not recommended for new implementations.
- Conclusion: **reached Stage 2** (1 → 2) with that note. [JHD](../../people/JHD.md) and [MF](../../people/MF.md) are the Stage 2.7 reviewers.
