## Continuation: Map take for stage 1, 2, or 2.7

- 提案ページ: [Map get and delete](../../proposals/map-get-and-delete.md)
- proposal: [proposal-Map-take](https://github.com/dcrousso/proposal-Map-take)
- 前日からの continuation。[DRO](../../people/DRO.md) が Map/WeakMap から値の取得と entry の削除を単一操作で行う新 method を提案し、Stage 1(可能なら 2/2.7)を要求。[JSL](../../people/JSL.md)/[ACE](../../people/ACE.md)/[DLM](../../people/DLM.md)/[MF](../../people/MF.md) らが Stage 1 を支持。
- 名称は `Iterator.prototype.take` との衝突を [KG](../../people/KG.md)/[MF](../../people/MF.md)/[CM](../../people/CM.md) が問題視し、`getAndDelete` へ rename する方向に。Set/WeakSet への追加は前日 [MM](../../people/MM.md)/[WH](../../people/WH.md) が symmetry から希望したが、Set に `get` がなく `delete` が在否を boolean で返すため不要と整理([MF](../../people/MF.md)/[NRO](../../people/NRO.md)、[WH](../../people/WH.md) も不要と同意)。
- key 不在時に `undefined` が返る曖昧さは既存の `Map.prototype.get` にも共通する問題であり([KG](../../people/KG.md))、[MF](../../people/MF.md) はこの method 単体でなく設計空間の探索を Stage 2 の前提として要求。
- 即時の Stage 2 には [CDA](../../people/CDA.md)/[MF](../../people/MF.md) が否定的だが、[ACE](../../people/ACE.md) は設計確定後に次回会合で Stage 1 から 2.7 へ直行も可能と見立て、spec reviewer を事前に volunteer。
- 結論: **Stage 1 到達**。`getAndDelete` へ rename し、Set/WeakSet には追加せず、undefined 値と key 不在を区別する方法を引き続き検討。

## JSON.parseImmutable

- proposal: [proposal-json-parseimmutable](https://github.com/tc39/proposal-json-parseimmutable)
- [Records & Tuples](../../proposals/records-and-tuples.md) の companion として始まった Stage 2 提案の update。withdrawal 後は「deeply frozen な object を返す JSON parse」として継続しており、PKA/[ACE](../../people/ACE.md) が open issues の状況を報告。
- 名称は champion が `JSON.parseFrozen` を選好、[KG](../../people/KG.md) は `parseToFrozen` を提案、[EAO](../../people/EAO.md) は `JSON.parse` に options bag(`frozen: true`)を渡す形を強く選好。
- 返り値の null prototype 化は [KG](../../people/KG.md)/[MF](../../people/MF.md) が強く支持(prototype 経由で Function constructor に到達する security bug への対策)。ただし frozen と null prototype は直交する option に分離しうると [KG](../../people/KG.md)。
- reviver の扱いは、第 2 引数の reviver の位置に options bag を渡す [KG](../../people/KG.md) 案が好評([ACE](../../people/ACE.md)/[EAO](../../people/EAO.md) 支持)。default は現行挙動(mutable)であるべきと [KG](../../people/KG.md)/PKA が整理し、LGH は JSON modules(import attributes)への鏡映を希望。
- 結論: 正式な consensus はないが、options bag API への移行に好意的な反応。作業を継続し committee へ再提示する。

## Error code property for Stage 2 or 2.7

- 提案ページ: [Error code property](../../proposals/error-code-property.md)
- proposal: [proposal-error-code-property](https://github.com/tc39/proposal-error-code-property)
- [JSL](../../people/JSL.md) が `cause` と同様に non-enumerable な own property として Error に `code` を追加する提案の Stage 2(可能なら 2.7)を要求。spec text・test262 の draft・V8 の draft 実装が揃い、editor review も開始済み。
- 唯一の未解決点は [AVK](../../people/AVK.md) が提起した DOMException との衝突。DOMException は numeric な `code` を prototype getter として持つが、WHATWG はこれを legacy 扱いし `.name` を使う方針と [KG](../../people/KG.md) が説明。[JSL](../../people/JSL.md)/[JHD](../../people/JHD.md) は実質的な conflict はないとの立場で、ecosystem の慣行上 `.name` への転用はむしろ breaking と [JSL](../../people/JSL.md)。
- [KG](../../people/KG.md) は DOMException との coherent な story なしに Stage 2 を超えることに反対し、[KM](../../people/KM.md)/[MM](../../people/MM.md)/[CDA](../../people/CDA.md) も 2.7 でなく 2 までを支持([LVU](../../people/LVU.md) は 2.7 も支持)。[MM](../../people/MM.md) は SuppressedError にも options bag が追加され `cause`/`code` を渡せることを確認して支持。
- 結論: **Stage 2 到達**。以降の advancement は DOMException との整合が条件で、整合の道筋を issue として提案するよう募った。

## Declarations in Conditionals for Stage 2 or 2.7

- proposal: [proposal-Declarations-in-Conditionals](https://github.com/tc39/proposal-Declarations-in-Conditionals)
- [DRO](../../people/DRO.md) が `if`/`while` の条件部での変数宣言を許す提案の Stage 2 を要求。Tokyo 会合の指摘を受け正式な spec text を整備し、binding は `else` では不可視(参照は TDZ で ReferenceError)とする設計に更新。
- `else` での可視性が最大の争点。[OFR](../../people/OFR.md)/NPU は C++ 同様に可視を強く要求、[KG](../../people/KG.md)/[MF](../../people/MF.md)/[CM](../../people/CM.md)/[MM](../../people/MM.md) は不可視を支持。[KG](../../people/KG.md) は `using` の早期 dispose(Rust の lock 解放 deadlock の教訓)をこの提案の最大の motivation とした。
- runtime の TDZ error には支持がなく、[KM](../../people/KM.md)/[MM](../../people/MM.md)/[WH](../../people/WH.md) は early error(SyntaxError ないし early ReferenceError)を主張し [DRO](../../people/DRO.md) も同意。[LVU](../../people/LVU.md)/[JRL](../../people/JRL.md) はそもそも error にせず外側 binding の参照を許す方が block scoping と一貫すると異論。
- [JHD](../../people/JHD.md) が欠席の [RBN](../../people/RBN.md) の position を代理し、pattern matching との cross-cutting concern 未解決を理由に Stage 2/2.7 を block。[MM](../../people/MM.md) も refutable な pattern の観点から現時点の advancement に反対、[MF](../../people/MF.md) は調整期限を次回会合までの 1 回分とした。
- 結論: advancement なし。pattern matching champion との調整と、`else` での binding 参照を early error とするか許容するかの決定が持ち越し。

## Async iterator helpers open questions

- Slides: [link](https://docs.google.com/presentation/d/17_mL3guxupbKWKr1EbDdML9K9kPTqElbf9xgoZZDBh0)
- [KG](../../people/KG.md) が concurrent な async iterator helpers(map/filter/flatMap と buffered)の設計 update(advancement 要求はなし)。userland 実装と interactive demo を公開し、order-preserving、helper による underlying iterator の所有、値を失わない、`{done: true}` の後の `{done: false}` は incoherent、という design principles を提示。
- mapper/predicate が primitive を返す場合に await の microtask tick を skip する fast path は、[NRO](../../people/NRO.md)/[JHD](../../people/JHD.md) の賛同を得て合意。
- incoherent な underlying iterator への防御と、map のみ可能な out-of-order の早期 delivery が争点。[MM](../../people/MM.md) は filter との一貫性から defensive(早期 delivery しない)側を選好、[WH](../../people/WH.md)/[KG](../../people/KG.md)/[SHS](../../people/SHS.md)/[RGN](../../people/RGN.md) は well-behaved な利用者に ill-behaved なケースの代償を課すべきでないと反対。
- mapper が throw した際は underlying の `return` を await してから error を届ける等の error 順序も整理。時間切れで残りの open questions は次回へ。
- 結論: primitive 返り値に対する await の skip に committee が合意。他の open questions は未解決のまま持ち越しで、さらに多くの議論時間が必要。

## Composites update

- Slides: [link](https://docs.google.com/presentation/d/1vTRHdRzIZQF69Q5Nx_VDkCkm2mn1rJK-CTtDiSqA9x0/)
- [Records & Tuples](../../proposals/records-and-tuples.md) の後継として compound な Map/Set key を実現する composites の update。[ACE](../../people/ACE.md) が interning あり/なし両方式の実験実装 benchmark を提示し、key の component 数と反復回数で優劣が入れ替わるがいずれも `JSON.stringify` より高速(object shape ごとの key sort cache が鍵)。
- [MM](../../people/MM.md) は性能でなく Map/Set/`Array.prototype.includes` の spec 改訂が不要になる点から interning を強く支持([SHS](../../people/SHS.md) も +100)。registered Symbol と同様に communication channel を作らないことも [MM](../../people/MM.md) が確認。polyfill が既存 method の patch を要しない点も [ACE](../../people/ACE.md) が利点とした。
- WeakMap/WeakSet への格納は、有限な lifetime の member を含む場合も含めて一律不許可の方向(registered Symbol の precedent を [MM](../../people/MM.md) が支持)。isComposite 的な predicate は追加する意向。
- `{a: 1}` と `{a: 1, b: undefined}` を同一 key とするか(undefined の drop)は、[ACE](../../people/ACE.md)/[EAO](../../people/EAO.md) が drop を選好する一方、[MF](../../people/MF.md)/[KG](../../people/KG.md) は undefined も通常の値として respect すべきと反対し、意見が割れた。
- 結論: interning 方式へ pivot し、composites の weak な保持は不許可とする。undefined の扱いは継続議論とし、Stage 2 要求の前に再度 committee へ持ち込む。
