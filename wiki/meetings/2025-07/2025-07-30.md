## Module Import Hook and new Global for Stage 1

- slide: [link](https://github.com/endojs/proposal-new-global/blob/main/slides/slides.pdf)

KKL と [ZTZ](../../people/ZTZ.md) が、realm から global を分離する新しい `Global` constructor と import hook の提案を Stage 1 に向けて発表した。Compartment/サンドボックス用途や AI 生成コードの分離、test runner・他ホストのエミュレーションなどが動機として挙げられたが、[KG](../../people/KG.md)・[MAG](../../people/MAG.md)・[JHD](../../people/JHD.md) らから「サンドボックスに見えるが実際はサンドボックスではない」という強い懸念、HTML 仕様が realm と global を一対一と仮定している実装上の懸念([MAG](../../people/MAG.md))、import map との重複([KG](../../people/KG.md))など多くの異論が出た。時間切れとなり、問題文(problem statement)を見直す必要があるという結論で当日はテーブル送りとなった(継続審議は同日後半の Continuation セッションへ)。

## Import Buffer for Stage 1

- slide: [link](https://proposal-import-buffer.vercel.app/)

STY(Vercel)が import attributes を使い任意のバイト列をモジュールとしてインポートする `import buffer` 提案を発表した。当初 `ArrayBuffer` での提案だったが、[NRO](../../people/NRO.md)・[JSL](../../people/JSL.md)・[KM](../../people/KM.md)・[MM](../../people/MM.md) らの支持により `Uint8Array`(immutable な `ArrayBuffer` を裏に持つ)へ変更され、属性名も `type: "buffer"` から `type: "bytes"` へ変更することで合意した。仕様の主要設計が固まっていることが確認され、Stage 1 だけでなく Stage 2 まで consensus が得られた(`Import Bytes has Stage 2`)。[EAO](../../people/EAO.md) が提案した `type: "text"` の追加は別提案として持ち越しとなった。
