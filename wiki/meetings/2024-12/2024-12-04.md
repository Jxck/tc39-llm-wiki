## Import Sync discussion, request for Stage 1?

- wiki: [Import Sync](../../proposals/import-sync.md)
- proposal: [proposal](https://github.com/guybedford/proposal-import-sync)
- slide: [link](https://docs.google.com/presentation/d/1GW_OCoVjd6OJi9BKSlQzQKqxrB0GUKHKFof4s3rn9yk/edit)

[GB](../../people/GB.md) presented demand for synchronous module access (Node PR #55730's `import.meta.require`; Bun already allows `require` in ESM), warning platforms will otherwise invent divergent importers. Use cases: sync access to built-ins, conditional loading, already-loaded dependencies, and sync execution for module virtualization. The sketched `import.sync` would have roughly [import defer](../../proposals/import-defer.md) semantics. [ACE](../../people/ACE.md) pushed back that Bloomberg is removing exactly these load-order assumptions; [SYG](../../people/SYG.md) worried about a new sync path and browser/server divergence ("let my crankiness be noted in the notes"); [JSL](../../people/JSL.md) preferred standardizing over chasing Node. [GB](../../people/GB.md) reframed the ask as Stage 1 for the **problem space**, not the design.

The conclusion was Stage 1 for exploring the sync-import problem space (support from [MM](../../people/MM.md), [JWK](../../people/JWK.md), [KKL](../../people/KKL.md); [SYG](../../people/SYG.md) explicitly noting no current path to Stage 2), with [MM](../../people/MM.md) asking for coordination with XS's `importNow`.

## ESM phase imports for Stage 2.7

- wiki: [ESM Phase Imports](../../proposals/esm-phase-imports.md)
- proposal: [proposal](https://github.com/tc39/proposal-esm-phase-imports)
- slide: [link](https://docs.google.com/presentation/d/1qfnmqPkpuAqTv-1pll1Y6EkEHElf_58BtNBQSw9dpq8/edit#slide=id.g305421a9f36_0_11)

[GB](../../people/GB.md) reported on the four Stage 2 investigations for the JS `ModuleSource`. Cross-spec: HTML and WebAssembly CG showed interest without concerns, and a draft HTML PR proves out `new Worker(source)`. Keying: URL+attributes as primary key with source text as secondary, so importing a source always yields an instance of **that** source ([MM](../../people/MM.md) probed per-transfer uniqueness). The source/instance ModuleRecord refactor is postponed in favour of "ghost" instances ([MM](../../people/MM.md), [NRO](../../people/NRO.md): the refactor would read better but is a lot of work). [KKL](../../people/KKL.md) generalized per-compartment canonical instances into "cohorts". [SYG](../../people/SYG.md) asked that cross-spec advancement move in lockstep; [DLM](../../people/DLM.md) cited the [ShadowRealm](../../proposals/shadowrealm.md) precedent for resolving it at 2.7.

The conclusion was Stage 2.7 by conditional consensus — [MM](../../people/MM.md) objects for now only on time-to-review grounds and will approve asynchronously after TG3 discussions before the next plenary; [JHD](../../people/JHD.md) asked for a tracking issue to record the approval.
