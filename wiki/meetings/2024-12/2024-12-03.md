## Briefing on the formation and goals of TC55 (or, All About Moving the WinterCG into Ecma)

- slide: [link](https://docs.google.com/presentation/d/1WnqF7y52QlPRw737ZOTC4rdmJ65-nT9BbOD05jr2sjE/edit?usp=sharing)

[JSL](../../people/JSL.md) (Cloudflare) explained why WinterCG is moving from a W3C community group into Ecma as **TC55**: the group's "minimum common API" draft immediately drew compliance claims but a community group cannot publish anything normative, and questions like server-side `fetch` semantics and streaming WebCrypto need a real standardization home. The charter's core work is defining the minimum common API (a subset of web platform APIs, verified via a profile of web-platform-tests) plus optional conformance levels for CLI/sockets-style runtimes, working through WHATWG/W3C processes rather than forking them. [SYG](../../people/SYG.md) asked why not the W3C working-group route (as WebAssembly did); [LCA](../../people/LCA.md) said the group consensus simply landed on Ecma's process and invited-expert policy. [CM](../../people/CM.md) confirmed the TC53 (embedded) overlap is deliberately coordinated, and [PFC](../../people/PFC.md)/[ABO](../../people/ABO.md)/[MAH](../../people/MAH.md) noted the minimum common API should be a superset of the web's `Exposed=*` set — with [JSL](../../people/JSL.md) adding TC55 is a good venue for questions like which APIs a [ShadowRealm](../../proposals/shadowrealm.md) gets.

The conclusion was an informational briefing: work closely with TC39, TC53, WHATWG etc., and workshop the charter language differentiating TC55 from TC53.

## Stabilize to stage 1

- wiki: [Stabilize](../../proposals/stabilize.md)
- proposal: [proposal](https://github.com/Agoric/proposal-stabilize)
- slide: [link](https://docs.google.com/presentation/d/1474EreKln5bErl-pMUUq2PnX5LRo2Z93jxxGBNbZmco/edit?usp=sharing)

[MM](../../people/MM.md) proposed unbundling JavaScript's integrity levels into orthogonal "integrity traits", motivated by three weaknesses in today's frozen/sealed/non-extensible system: the **return override** mistake lets subclass constructors graft private fields onto pre-existing objects (breaking fixed-shape structs — all fast engines implement private fields as a hidden shape change), the **assignment override** mistake breaks legacy prototype code when primordials are frozen, and **proxy handler traps** are the one unvalidatable source of re-entrancy hazards (a `non-trapping` trait would make proxies on frozen targets act exactly like their targets). A full unbundling costs ten new proxy traps, so the champions' minimal picture keeps non-extensible bundled and folds overridable/non-trapping into a `stable` trait, with `fixed` broken out separately. [SYG](../../people/SYG.md) supported Stage 1 for structs' sake and floated V8's preference to retcon non-extensible to imply `fixed` (a use counter is deployed to check the wild); [KG](../../people/KG.md) welcomed the exploration but warned object-model states are conceptually expensive for developers; [NRO](../../people/NRO.md) argued the unbundled picture is actually simpler to explain and asked for a glossary.

The conclusion was Stage 1 (explicit support from [SYG](../../people/SYG.md), weak support from [JWK](../../people/JWK.md), plus [JHD](../../people/JHD.md)).

## Module Harmony: where we are

- slide: [link](https://docs.google.com/presentation/d/1V2-4Hj-HBVQwdphcJUsrbmbitOPBMSf3HhKSvhBk4d0/edit?usp=sharing)

[NRO](../../people/NRO.md) gave the yearly re-introduction of the module Harmony landscape, no normative asks: [import attributes](../../proposals/import-attributes.md) is Stage 4, source phase imports is Stage 3, [ESM Phase Imports](../../proposals/esm-phase-imports.md) is heading to 2.7 this meeting, and [import defer](../../proposals/import-defer.md) is at 2.7. The big structural shift: thanks to [GB](../../people/GB.md)'s phase-imports machinery, **module expressions/declarations no longer depend on a ModuleInstance concept** — they become syntax over JavaScript `ModuleSource`s — and the worker-from-source use case that motivated ModuleInstance imports is solved, so that proposal is no longer discussed. Static analysis moved out of [ESM Phase Imports](../../proposals/esm-phase-imports.md) to live with the future module loader hooks proposal. Three clusters: the ModuleSource cluster (source phase, phase imports, module declarations, shared-struct prototype identity via shared ModuleSources — [KKL](../../people/KKL.md) on "cohorts" of module instances), the optional/sync evaluation cluster ([import defer](../../proposals/import-defer.md), deferred/optional reexports, sync dynamic imports), and the custom loaders/compartments cluster (little progress; help welcome).

The conclusion was a status overview to set common ground for the module presentations later in the meeting; feedback on the format welcome.

## Immutable ArrayBuffer to stage 2

- wiki: [Immutable ArrayBuffers](../../proposals/immutable-arraybuffer.md)
- proposal: [proposal](https://github.com/tc39/proposal-immutable-arraybuffer)
- slide: [link](https://github.com/tc39/proposal-immutable-arraybuffer/blob/main/immu-arraybuffer-talks/immu-arrayBuffers-stage2.pdf)

[MM](../../people/MM.md) asked for Stage 2, with the spec text at Stage 2 quality ([RGN](../../people/RGN.md)) and a full implementation in Moddable's XS. Decisions: `transferToImmutable` **gains the optional length parameter** ([MM](../../people/MM.md) reversing himself — it "minimizes the damage from surprise"; [WH](../../people/WH.md) and [MAH](../../people/MAH.md) concurred), with [SYG](../../people/SYG.md) noting length expansion may break the zero-copy expectation (zero-filled on-demand pages; "my blind spot is windows") and [KG](../../people/KG.md) fine with non-zero-copy expansion. A `ArrayBuffer.prototype.subarray` alternative from [JLS](../../people/JLS.md) was rejected ([SYG](../../people/SYG.md): "ArrayBuffers are never windows... and TypedArrays are"). `sliceToImmutable` (zero-copy window onto an immutable buffer, e.g. to hand a TypedArray a subset without revealing the whole buffer) drew a concrete-use-case challenge from [SYG](../../people/SYG.md) ("I'm on the fence about this inclusion barring a concrete motivation") while [WH](../../people/WH.md) wanted to allow (not mandate) zero-copy. On the mutable-vs-immutable accessor name, [JHD](../../people/JHD.md) argued for positive naming with absence-equals-false; [KG](../../people/KG.md) noted the accessor is always present so the absence argument is weaker. On failure modes [SYG](../../people/SYG.md) pushed to align with whatever detached/out-of-bounds already does ("I have zero interest in working on this part of the code"), against [MM](../../people/MM.md)'s "when in doubt, throw" bias.

The conclusion was Stage 2 (support from [WH](../../people/WH.md), [NRO](../../people/NRO.md), [JHD](../../people/JHD.md), [JLS](../../people/JLS.md), [CM](../../people/CM.md)), with order-of-operations and throw-vs-silent details to be settled in Stage 2 with implementer feedback.

## import defer updates

- wiki: [import defer](../../proposals/import-defer.md)
- proposal: [proposal](https://github.com/tc39/proposal-defer-import-eval/)
- slide: [link](https://docs.google.com/presentation/d/1yFbqn6px5rIwAVjBbXgrYgql1L90tKPTWZq2A5D6f5Q/)

[NRO](../../people/NRO.md) proposed concrete fixes to the two problems from last plenary. First, to keep the proposal implementable by tools, **any query that depends on the module's contents now triggers evaluation** — including `Object.keys`/`getOwnPropertyNames`/`getOwnPropertyDescriptor` on the namespace (string-keyed `get` already did; symbol keys don't, since symbol-named exports can be ruled out without the contents). [GB](../../people/GB.md) questioned expanding triggers for polyfillability at the cost of a real use case (feature-detecting a deferred namespace's exports before evaluating) and warned hosts may skip early export validation; [NRO](../../people/NRO.md) answered the spec still requires eager syntax/link errors, and [SYG](../../people/SYG.md) sided with designing for today's tools in the ESM space ("the dream of using ESMs outside of bundlers is a long ways off"); [JHD](../../people/JHD.md) added polyfillability should surface issues but not guide design. Second, since `import.defer(...)` resolves a promise whose `then` lookup always triggered evaluation, the fix is to **hide `then` on deferred namespace objects** entirely (consensus reached). Consensus was also reached on a distinct `toStringTag` ("deferred module") for debuggability, with [JHD](../../people/JHD.md) noting it is not a brand check — namespace objects remain unbrand-checkable. A `Symbol.evaluated`-style evaluated-state probe got support in principle ([KG](../../people/KG.md): capability good, new well-known symbol bad; [MM](../../people/MM.md) sketched integrating it with the [Stabilize](../../proposals/stabilize.md) non-trapping trait) but was left for a follow-up.

The conclusion was consensus on the trigger expansion, hiding `then`, and the `toStringTag` change; the contested key-list-triggering slide 7 got a 2-2 temperature check deferred to a continuation; editors' spec review is the remaining Stage 2.7 condition, with Stage 3 targeted for next meeting.

## Error Stacks Structure for Stage 2

- proposal: [proposal](https://github.com/tc39/proposal-error-stacks)

[JHD](../../people/JHD.md) revived the error-stacks proposal, unchanged since its failed 2019 Stage 2 attempt: it specifies only the **structure** — `Error.prototype.stack` as a normative-optional accessor plus static `getStack`/`getStackString` — leaving the frame contents implementation-defined, so stack traces "can't get any worse" structurally and userland no longer parses stack strings ([MM](../../people/MM.md), co-champion: scraping strings can never be conformant since function names may contain parens; an agreed schema is "a hell of a lot better than nothing", comparing to for-in order being narrowed over years). [SYG](../../people/SYG.md) pressed that the proposal doesn't say what populates the `[[ErrorData]]` slot, so it doesn't deliver the interoperability that is the actual goal ("what does this make better?"); [MAG](../../people/MAG.md) called it "multiple proposals in a trench coat" — the accessor, the string format (which he thinks can never ship), and the structured API should be split, and suggested implementations stay free to drop frames; [DLM](../../people/DLM.md) registered a blocking SpiderMonkey concern about forcing engines to converge internal representations; [WH](../../people/WH.md) preferred keeping the big picture in one proposal over splitting.

The conclusion was no advancement: the champion plans to bring a new, smaller proposal for just the existing stack accessor (which later became [Error Stack Accessor](../../proposals/error-stack-accessor.md)), with the existing proposal to "rebase" on top of that as it advances.
