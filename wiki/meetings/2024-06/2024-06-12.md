## ShadowRealm Update

- wiki: [ShadowRealm](../../proposals/shadowrealm.md)
- proposal: [proposal](https://github.com/tc39/proposal-shadowrealm)
- slide: [slides](https://docs.google.com/presentation/d/1HxocWS0WfIZPanCAhsabSDOPx9LCjw6upMfMP9ogEqE/)

[PFC](../../people/PFC.md) gave a quick status update on [ShadowRealm](../../proposals/shadowrealm.md) work at Igalia in partnership with Salesforce. Since the February plenary, the "confidentiality" criterion for which web APIs to include has collected feedback from the HTML reviewers and Mozilla, the latter reporting difficulties with WPT coverage — coverage of ShadowRealms created inside different realm types (e.g. workers) is wanted. Short-term work is simplifying the confidentiality criterion to remove confusion, addressing Mozilla's WPT concerns, and getting the ShadowRealm HTML integration PR into a mergeable state. [DE](../../people/DE.md) (inserted later) recommended the criterion "ShadowRealms should contain the intersection of what's in all conceivable environments", which implies excluding everything to do with I/O, and said the principle should be documented in the W3C TAG design principles. [MAG](../../people/MAG.md) thanked the team for the much-improved WPT state.

No advancement was requested; this was a status update.

## Sourcemaps Progress Updates

- proposal: [source-map](https://github.com/tc39/source-map)
- slide: [slides](https://docs.google.com/presentation/d/1H6nu-Q0FllP2rsnCRxepiB_iBgsA0TMba5FGntDL5fg/)

JKP (with BEL presenting the testing half) gave an in-depth TG4 sourcemaps update instead of the usual short one, covering the group's constituencies (generators, debuggers, error monitoring tools — with Sentry and replay.io joining TC39), the TG-internal staging process, and the spec fixes already merged into the draft: pinning `version` to 3, specifying `sourceMappingURL` comment vs `sourcemap` HTTP header precedence (the header wins), removing the unused `url` field, `ignoreList` replacing `x_google_ignoreList` and deprecating `x_` extensions, defining Wasm columns as byte offsets, and rewriting fetching in terms of the fetch API. An open question is how to specify locating the `sourceMappingURL` comment: a fast-but-imprecise regex or an accurate-but-slow full parse as an "either/or"; [LCA](../../people/LCA.md) asked whether generators would be required to emit parsable comments (no generator-side text exists yet), and [WH](../../people/WH.md) probed the security angle — browsers only fetch sourcemaps with devtools open, and JKP will file an issue on attacker-controlled URLs. Three new feature proposals were described: scopes (`originalScopes`/`generatedRanges` to reconstruct scopes, variables and inlined functions), range mappings (preserving fidelity through multi-step build chains), and debug ID (early stage; needs WHATWG cooperation to surface the ID at error time). BEL presented the validator (checking mappings rather than exact output, since generators legitimately differ) and the consumer test suite (JSON test cases with harnesses landed in Firefox and in progress for Chrome devtools), noting findings such as lenient consumer validation, the imprecise 32-bit VLQ limit, and underspecified index maps. [CM](../../people/CM.md) and [RGN](../../people/RGN.md) praised the thoroughness and TG4's autonomous working style; [RPR](../../people/RPR.md) asked which constituencies remain unengaged (compiler/Rust, WebAssembly, error-monitoring SaaS, Apple/WebKit — [MLS](../../people/MLS.md) noted WebKit is not yet sending participants).

The conclusion was no advancement sought — an update to spread awareness and gather feedback.

## Nova JavaScript Engine—Exploring a data-oriented engine design

- slide: [slides](https://docs.google.com/presentation/d/1Pv6Yn2sUWFIvlLwX9ViCjuyflsVdpEPQBbVlLJnFubM/edit?usp=sharing)

AAI (Aapo Alasuutari, Valmet) repeated his Web Engines Hackfest talk on Nova, a hobby engine exploring data-oriented design: heap data lives in per-type vectors (struct-of-arrays) addressed by a tagged-union value holding a heap index instead of a pointer, objects are split into cache-line-friendly columns (prototypes, elements, properties), ordinary objects drop elements backing entirely, and arrays/ArrayBuffers keep a minimal layout with a "backing object" taking over when code does something exotic. GC compaction realigns indices (exploiting allocation-order locality), which yields a free nursery and no heap fragmentation. Claimed upsides: lower memory use, excellent cache-line utilization, and no pointers in values, making type confusion impossible since a tag selects both the type and which vector the data is read from. Downsides acknowledged: index properties and exotic objects are pessimized, GC and compaction performance are unproven (the current GC "mostly empties the whole heap"), and hash map reinsertion is a concern. Q&A touched on the structs proposal ([ACE](../../people/ACE.md)), primitive and string representation ([WH](../../people/WH.md): UTF-8 strings, small integers on the stack, doubles in heap vectors; incremental string construction is future work), space-vs-time trade-offs of bit-packing ([SFC](../../people/SFC.md)), and handling heterogeneous `JSON.parse` output ([CM](../../people/CM.md); bucketed by property count).

Informational talk; no committee decision was sought.

## Smart units progress update

- proposal: [proposal](https://github.com/tc39/proposal-smart-unit-preferences)
- slide: [slides](https://docs.google.com/presentation/d/1WCdpcX4IpObi0CD1ftXA9QbZL5RSEGlYGXdqw3EfIdg/)

[BAN](../../people/BAN.md) revisited the smart units proposal from several years ago: localizing measurements to the unit scale and precision appropriate to the locale, usage context and magnitude (e.g. person-height in feet and inches, Finnish wind speed in m/s, Swedish Scandinavian miles), with the data already in CLDR's supplemental/units.xml (~8 KB). The proposed API is a `usage` string option on Intl.NumberFormat, with non-goals including arbitrary unit conversion, clothing sizes, and every context-specific variation, and no new fingerprinting surface. Questions posed to the committee: how to support mixed units, how to handle the en-US problem (about 70% of Mozilla users in Indonesia use en-US; [BAN](../../people/BAN.md) floated a permission-prompt-style approach), and whether the conversion belongs in ECMA-402. In discussion, [MF](../../people/MF.md) asked about discoverability and the target user ([DE](../../people/DE.md): MDN, plus publishing the supported-unit list), [MAG](../../people/MAG.md) about CLDR maintenance and how additions reach browsers ([USA](../../people/USA.md): via engine ICU updates), and [SFC](../../people/SFC.md) recalled the metric used to pick the original 45 units and argued for a similar metric for usage contexts. [EAO](../../people/EAO.md)'s main concern was misuse as a general unit-conversion API, arguing the proposal should expose a good explicit conversion path if it converts at all, while [SFC](../../people/SFC.md) countered that CLDR-driven rounding keeps it unusable for general conversion and developers should keep bringing their own libraries. [DLM](../../people/DLM.md) suggested Canadian construction units and flagged unit-pricing output as a parsing temptation; [SFC](../../people/SFC.md) reported a snap poll at Monday's community event (~70% found it useful, dropping to ~40% once the en-US issue was factored in) and sees room for locale extensions later; [JGT](../../people/JGT.md) suggested positioning it as plumbing for small userland libraries.

The conclusion was discussion only — no advancement was requested; next steps are determining the supported set and ways to prevent misuse.

## Cancellation: Room for improvement

- slide: [slides](https://docs.google.com/presentation/d/1ge28UQnISRaDfHp5IFz1XNAJnQm2aGjaqZJeAY3fk5Q/)

[DE](../../people/DE.md) (presenting content developed with [RBN](../../people/RBN.md), who was unwell) reviewed the state of cancellation years after the cancellable-promises discussions: how AbortController/AbortSignal meet the goals of avoiding unnecessary work, unlinking data structures, nesting (AbortSignal.any trees) and separation of concerns; where they fall short (no reference counting, no way to drop cancellation reactions, EventTarget-based misuse such as dispatchEvent and onabort overriding, and no way for TC39-defined APIs like timers or signals to accept a signal); and possible strategies (host hooks accepting AbortSignal, moving the API to TC39, or defining a different cancellation API). Implicit threading of an ambient signal via [AsyncContext](../../proposals/async-context.md) was proposed, with an explicit `{ signal: "inherit" }` opt-in. In the queue, [NRO](../../people/NRO.md) noted he uses AbortController across Node and browsers and finds it odd the capability is not in the language; CHU and [LCA](../../people/LCA.md) described heavy adoption ([LCA](../../people/LCA.md): HTTP server request signals, which need library support downstream); [RBN](../../people/RBN.md) objected that implicit threading can break code that assumes it cannot be cancelled, preferring opt-in; [PFC](../../people/PFC.md) asked whether the API should take a position on cancellable-by-default.

The conclusion was to keep investigating — [DE](../../people/DE.md) and [RBN](../../people/RBN.md) will work with WHATWG and TC39 on these issues and invited others to join; no advancement was requested.

## Joint Iteration for Stage 2.7

- wiki: [Joint Iteration](../../proposals/joint-iteration.md)
- proposal: [proposal](https://github.com/tc39/proposal-joint-iteration)
- slide: [slides](https://docs.google.com/presentation/d/1Qj5h6MajJnji1obZsXea_cUgfwxur-yT6v-8rBTLqtg/)

[MF](../../people/MF.md) asked for Stage 2.7 with full spec text, a polyfill, and reviewer sign-off from [JHD](../../people/JHD.md) and [NRO](../../people/NRO.md), resolving three open questions in real time. Naming: the committee preferred `zip` over `zipToArrays` ([ACE](../../people/ACE.md), [RBN](../../people/RBN.md), [LCA](../../people/LCA.md); [MF](../../people/MF.md)'s own preference for explicit names was overridden; [KG](../../people/KG.md) regretted giving the convenient name to the form that invites iterator-protocol destructuring overhead). Strings: string inputs will not be implicitly iterated, consistent with iterator helpers ([LCA](../../people/LCA.md) asked for this to be a general committee precedent; [RBN](../../people/RBN.md) and [DMM](../../people/DMM.md) argued implicit string iteration has been a mistake). Options: the two booleans (longest/strict) are replaced by a single `mode` option of "shortest", "longest" or "strict" ([ACE](../../people/ACE.md), JKP, [RGN](../../people/RGN.md), [SFC](../../people/SFC.md); [RGN](../../people/RGN.md) noted string-valued modes have precedent in ECMA-402 and [Temporal](../../proposals/temporal.md)). Also decided since the last presentation: zipping zero iterators yields an already-exhausted iterator, and array-specific variants (e.g. `Array.zip`) remain controversial and were dropped — [JHD](../../people/JHD.md) intends to return with a separate Array.zip proposal for rapid advancement. [SYG](../../people/SYG.md)'s prepared statement said V8 dislikes the old names and the two-boolean options and supports omitting the Array method (`toArray()` exists), but does not block. [MM](../../people/MM.md) asked about coordination with async iterator helpers; [KG](../../people/KG.md) was confident the synchronous design carries over naturally.

The conclusion was Stage 2.7.

## Temporal Stage 3 update and scope reduction

- wiki: [Temporal](../../proposals/temporal.md)
- proposal: [proposal](https://github.com/tc39/proposal-temporal)
- slide: [slides](https://docs.google.com/presentation/d/1PPMAxVnVjFwRPuJwOvVsw9nZLQ6jDM8Hd5PNO0Grp4I/)

[PFC](../../people/PFC.md) and [JGT](../../people/JGT.md) reported on [Temporal](../../proposals/temporal.md)'s Stage 3 progress and a large scope reduction responding to implementer feedback (Google, Apple, Mozilla) that the proposal is too big for resource-constrained targets: V8's per-function binary/RAM cost and the complexity of custom calendars and time zones calling back into user code. The ISO string format with timezone and calendar annotations is now RFC 9557; implementations are under way in SpiderMonkey ([ABL](../../people/ABL.md)), Boa (including [JWS](../../people/JWS.md)), and a FullCalendar polyfill (Adam Shaw). Two normative fixes reached consensus: the PlainDateTime difference arithmetic bug (tc39/proposal-temporal#2838) and dropping Unicode minus signs from the ISO string grammar (tc39/proposal-temporal#2856 plus tc39/ecma262#3334 — observable for offset time zone names even without Temporal, per [RGN](../../people/RGN.md)). The scope reduction removes 96 of ~300 functions. Consensus was reached on removing: custom calendars (Temporal.Calendar and user calendars), custom time zones (Temporal.TimeZone and user time zones, with getNextTransition/getPreviousTransition consolidated into ZonedDateTime), the getISOFields methods, withPlainDate, PlainTime's toPlainDateTime and toZonedDateTime, the epochSeconds and epochMicroseconds properties (and Instant.fromEpochSeconds/fromEpochMicroseconds), direct PlainDateTime/ZonedDateTime to PlainYearMonth/PlainMonthDay conversions, Instant.prototype.toZonedDateTime, Now.zonedDateTime/plainDateTime/plainDate (the ISO variants stay), and the relativeTo option from Duration.add. Collapsing valueOf and toJSON into identical function objects was deferred pending a Mozilla feasibility investigation ([DLM](../../people/DLM.md); [ABL](../../people/ABL.md) raised implementation concerns) and returns next plenary. Removing subtract() (objected by [DE](../../people/DE.md), [LCA](../../people/LCA.md), CHU, [ACE](../../people/ACE.md)) and since() ([RBN](../../people/RBN.md) preferred keeping it) did not reach consensus. [JHD](../../people/JHD.md) raised process concerns — size and complexity could have been evaluated before Stage 3, and Temporal might belong back in 2.7 until these changes settle — but there was no consensus to change the stage; he also argued for reified Calendar/TimeZone objects to avoid stringly-typed APIs, and [SBE](../../people/SBE.md) pressed to keep the remaining shape conducive to re-adding declarative (iCalendar/jsCalendar-style) custom time zones, which [JGT](../../people/JGT.md) welcomed. [SYG](../../people/SYG.md)'s prepared statement strongly supported the scope reduction.

The conclusion was consensus on the two normative fixes and the removal batch (A-C, G-L); the subtract()/since() removals failed, the valueOf/toJSON collapse returns next plenary, and the stage is unchanged.
